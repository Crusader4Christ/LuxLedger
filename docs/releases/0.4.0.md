# LuxLedger 0.4.0

LuxLedger `0.4.0` is a coordinated breaking release. Upgrade all LuxLedger packages together:

| Component | Release version |
| --- | --- |
| `@luxledger/core` | `0.4.0` |
| `@luxledger/http` | `0.4.0` |
| `@luxledger/postgres-adapter` | `0.4.0` |
| `@luxledger/fastify-routes` | `0.4.0` |
| `@luxledger/express-routes` | `0.4.0` |
| OpenAPI `info.version` | `0.4.0` |

## Bounded credit reads

`GET /v1/accounts/{id}/credit-balance` now returns only the reconciled account summary. Its
unbounded `lots` array was removed. Read lots from the new
`GET /v1/accounts/{id}/credit-lots` endpoint with `limit` and `cursor`.

`GET /v1/credit-grants` lists grants and supports exact `account_id`, `reference`, and
`external_reference` filters. Grant and lot pages return `{ data, next_cursor }`.

Grant and transaction allocation endpoints are now cursor-paginated and use the same
`{ data, next_cursor }` envelope as grant and lot pages. Replace reads of `allocations` with `data`
and follow `next_cursor` until it is null.

Pagination orders by the exact PostgreSQL `created_at` value and immutable UUID tie-breakers. The
opaque cursor preserves PostgreSQL microseconds rather than reducing timestamps to JavaScript
millisecond precision. Cursors are versioned and bound to their endpoint, tenant, and filters;
restart from the first page when any filter changes.

## Database compatibility

Migration `0005_2026-10-17-add-credit-grant-list-index.sql` adds the
`(tenant_id, created_at, id)` index used by tenant-wide grant pagination. It does not transform
existing rows. Apply it after the complete `0.3.0` migration chain and before starting `0.4.0`
application instances.

## Upgrade checklist

1. Upgrade all five LuxLedger packages to `0.4.0` and regenerate the consumer lockfile.
2. Replace reads of `credit-balance.lots` with paginated calls to `credit-lots`.
3. Apply migration `0005_2026-10-17-add-credit-grant-list-index.sql`.
4. Follow `next_cursor` on grant, lot, and allocation-lineage reads until it is null.
5. Refresh generated clients from the `0.4.0` OpenAPI document.
6. Run contract, type, unit, and PostgreSQL integration tests before deployment.
