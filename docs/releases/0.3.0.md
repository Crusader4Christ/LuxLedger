# LuxLedger 0.3.0

LuxLedger `0.3.0` is the first coordinated release of the current pre-production
package and migration set. All public LuxLedger packages and the OpenAPI
contract use version `0.3.0`.

| `@luxledger/core` | `0.3.0` |
| `@luxledger/http` | `0.3.0` |

| `@luxledger/express-routes` | `0.3.0` |
| OpenAPI `info.version` | `0.3.0` |

## Breaking entry contract

Transaction and hold entries now use one non-zero `signed_amount_minor` field:

- positive values are DEBIT entries;
- negative values are CREDIT entries;
- every transaction and hold must sum to zero.

Core callers use `signedAmountMinor: bigint`. HTTP callers send the signed
decimal string and derive any display direction from its sign.

```json
{
  "account_id": "00000000-0000-4000-8000-000000000101",
  "signed_amount_minor": "-1250",
  "currency": "USD"
}
```

## Additional release surface

- Tenant assets are registered explicitly before accounts or postings use their
  currency code.
- Accounts can opt into immutable credit-grant capability with `grant_enabled`.
- Credit-grant create, read, reversal, expiration, allocation, and
  `GET /v1/accounts/{id}/credit-balance` endpoints are included.
- Transactions accept and return immutable nullable JSON-object `metadata`.
- Grant-backed holds reserve exact grant lots; partial commit and void preserve
  allocation lineage and reservation capacity.

## Migration chain

The checked-in pre-production chain is:

1. `0000_initial-schema.sql`
2. `0001_grant_account_capability.sql`
3. `0002_2026-10-06-signed-entry-amounts.sql`
4. `0003_transaction_metadata.sql`
5. `0004_grant_hold_allocations.sql`

This project has no production database or supported legacy deployment to
upgrade. Development databases created from retired migration files should be
recreated from the current chain.

## Verification

- `bun run test:ci` runs unit and real-PostgreSQL integration coverage,
  including the signed-entry transformation fixture.
- `bun run contract:verify` checks runtime HTTP schemas against the canonical
  OpenAPI document.
- `bun run release:verify` and `bun run pack:verify` validate the coordinated
  versions, exports, and packed package contents.
- `bun run migration:verify` validates a clean migration plus backup/restore;
  it is not an upgrade test for `0002`.
- The demo runs `npm run verify:openapi`, which resolves the OpenAPI file from
  the installed `@luxledger/http` package and compares it byte-for-byte with
  its checked-in copy.
